CLI & Settings

Use this page once you have a workspace. run, parse, verify, and repair call a model. To read what has already been recorded, use status to see which reviews still apply or export to read the proof and its citations; neither needs a running server.

Subcommands

For commands on a conjecture, DIR is its bare name inside a workspace (e.g. parity) or a path to the directory containing conjecture.md. LEMMA_ID is a full ID from the run log or HTML graph (e.g. alice/3f9a2c1b4d5e6f70/7d1e90), not a filename or just the last six digits. init and migrate take a workspace directory instead.

SubcommandDescription
proofs config [--global] KEY [VALUE]Read, set, or remove user.id, user.name, and user.email in ~/.config/proofs/config. Use --list to see current values.
proofs init [DIR]Initialize a workspace: creates conjectures/, .proofs, .proofs-local.json (defaults, plus blank model entries and routes to fill in), and updates the managed .gitignore block.
proofs new NAMECreate conjectures/NAME/ with a blank statement and notes, an empty references/ directory, and references.md initialized to []. An existing name is refused.
proofs run DIR [FLAGS]Run the serial or --parallel N proving loop on a conjecture.
proofs parse DIR [FLAGS]Maintainer tool: parse local references/ files into committed references.md.
proofs verify DIR LEMMA_ID [--full]Check a stored lemma. Add --full to check everything it depends on, --tools ... --run-code to rerun its scripts, or --parallel N to run verifier checks in parallel.
proofs verify DIR --uncertifiedVerify every suspended lemma whose only fault is a missing certificate, from the roots up.
proofs repair PATH_TO_REFUTATIONRe-verify or re-prove a refuted lemma and repair affected dependents up the DAG.
proofs repair --all DIRRepair lemmas with a refutation that still applies. Start with their dependencies and try each lemma at most once.
proofs prune DIR [--with-dependents]Remove refuted lemmas, compact reproof chains, merge duplicate certificates, and clear stale scratch.
proofs status DIR LEMMA_IDPrint the lemma's citation closure: Merkle hashes, stream files, certificates, computations, suspension, and settlement.
proofs export DIR [LEMMA_ID] -o OUT --format ...Export the whole DAG, one --user, or a lemma's closure as latex, interactive html, or png. Add --suspended to include suspended lemmas, marked in red.
proofs limits DIRDisplay active code.* limits and which config layer each value came from.
proofs tools lock|check DIRlock writes tools.lock from flake.nix via nix eval; check verifies installed tools and sandbox availability.
proofs migrate [DIR]Rewrite a legacy format-1 workspace as format-2 streams. Commit or back up the workspace first and review the rewritten files before sharing.

Put run options after the conjecture name. For the full options of the proving loop, use proofs run parity --help in the workspace; for a verifier, use proofs verify --help. The numeric limits with corresponding config keys (such as --max-iterations) are in the settings table below.

.proofs-local.json Settings

For a lasting change on this machine, edit the workspace’s .proofs-local.json. For just one conjecture, use the same filename beside its conjecture.md and include only the keys that differ. Keys like "run.max_iterations" are literal JSON keys, not nested objects. Neither file belongs in Git. For example, this entire conjecture-level file gives the run a three-iteration budget: 

{
  "run.max_iterations": 3
}

With a default route set, proofs run parity --max-iterations 5 overrides that value for one invocation, without editing either file. A resumed run counts iterations already spent toward the five. For the integer settings below, -1 means no limit unless noted otherwise. See machine limits for code.* keys and routing for model entries.

Exports & Live Status Board

Export makes a snapshot; it does not change the workspace records. Give -o a directory (created if needed) and -n a filename without a path. For example, the following writes out/parity.html; open that file locally, or send it to someone who does not have Proofs installed: 

proofs export parity -o out -n parity --format html

Without -n, a whole-graph export is proof plus the format’s extension. Give a lemma ID after the conjecture name to export just its argument and everything it cites. Alternatively, --user alice selects Alice’s lemmas, not other contributors’ lemmas they cite. Suspended lemmas are left out unless you add --suspended, which includes them and marks them in red: red ringed dots in the graph, and a red “(suspended)” tag with the reasons in LaTeX. Choose the format according to what you want to read:

  • --format latex (.tex): dependency-ordered lemmas, cross-referenced citations, references section, and a verbatim Computations appendix with SHA-256 hashes and recorded RESULTs.
  • --format html (.html): an interactive citation graph with KaTeX included, so it works offline. Rows show depth, colors identify contributors, and larger dots indicate more citations. With --suspended, suspended lemmas are included as red dots ringed in red, and a double ring marks the lemma that settles the conjecture, always labelled with whether it proves or disproves it. You can pan, zoom, find a lemma by ID, trace a chain of citations, or switch between Light, Dark and Theme, which uses this site’s palette and follows your OS setting. --theme light|dark|proofs picks the one it opens in (default proofs).
  • --format png (.png): static citation graph rendered via matplotlib (up to 3840×2160, --theme light|dark|proofs|proofs-light, where proofs is this site’s palette and proofs-light its light variant).

During a run, the live board answers a different question from proofs status: what is each worker doing now? --ui auto uses it on an interactive terminal with rich installed. A verifier row with an increasing elapsed time means the request is in progress, not that a verdict has been issued. Use --ui plain for a scrolling record of all events rather than the most recent ones.

Workspace & Repository Layouts

The program repository contains the CLI (proofs/cli/) and default prompts (proofs/agents/). You do not edit those to add a problem. Below is the separate workspace for the parity example after some runs. Don’t worry if dags/, certificates/, or the optional code files don’t exist immediately after proofs new. 

# Workspace root (e.g. ~/my-proofs/)
.proofs                                  # workspace marker (format = 2)
.gitignore                               # managed proofs ignore block + your rules
.proofs-local.json                       # gitignored: machine limits, settings & llm.models/routes
conjectures/
  parity/
    conjecture.md                        # required: conjecture statement
    dags/<user>/<run>/000001.jsonl       # committed: append-only lemmas & reproofs
    certificates/<user>/<run>/*.jsonl    # committed: acceptances
    computations/<user>/<run>/*.jsonl    # committed: code execution records
    code/<user>/<run>/<sha256>.sage      # committed: scripts cited by proofs
    refutations/*.json                   # committed: active/stale refutations
    references.md                        # committed: parsed theorem collection
    flake.nix, flake.lock, tools.lock    # optional, committed: reproducible code tools
    references/                          # gitignored: maintainer-local source papers
    comments.md                          # gitignored: private planner notes
    checkpoints/<user>/<run>/            # gitignored: atomic checkpoints & locks
    scratch/<user>/<run>/                # gitignored: in-flight scripts
